# Brand

## Name

Use **Code Hands** in product-facing copy. The repository and package use the technical name `codehands-desktop`; that is not the display brand.

## Product promise

Code Hands helps people delegate a coding task, follow the work on their own machine, inspect the resulting changes, and decide what happens next. The desktop app is local-first: repository paths, agent credentials, and task execution belong on the device. Cloud account features should be described narrowly and accurately.

## Brand character

- **Capable, not theatrical:** emphasize useful work and clear outcomes.
- **Calm and trustworthy:** make task state, local/remote boundaries, and review decisions legible.
- **Technical, but approachable:** use familiar developer language without unnecessary jargon.
- **User-controlled:** communicate that changes are reviewable and decisions remain with the person.

## Visual identity

The interface uses a dark neutral foundation, soft violet as the primary brand accent, and restrained blue, green, amber, and red to distinguish information and status. Rounded, bordered surfaces and compact monospaced metadata give the app a precise workspace feel. The sidebar brand mark is a white “C” on a violet gradient; do not treat that CSS treatment as a separate approved logo asset.

## Voice and terminology

- Prefer short, direct labels and plain explanations.
- Say **local**, **on this device**, and **cloud** explicitly when the distinction matters.
- Use status language that describes what is happening (for example, “Waiting for review”), not vague success claims.
- Avoid claiming that a task is executing, synced, secure, or available unless the current product state supports that claim.
- Keep destructive or consequential actions explicit, and name their effect.

## Do

- Keep task progress and review decisions easy to scan.
- Make unavailable and planned features visibly distinct from active features.
- Use violet for brand emphasis, not as the only signal for task status.

## Avoid

- Marketing claims that imply remote code execution or upload repository contents.
- Using semantic status colors decoratively or interchangeably.
- Adding new brand colors or typography without updating the design references.
